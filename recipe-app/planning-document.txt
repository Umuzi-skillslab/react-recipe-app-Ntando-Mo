3. Component List & Purposes

App / Pages: App serves as the root router and wraps the application in the FavoritesContext. Route-level components (Home, RecipesPage, MealPlannerPage, FavoritesPage, RecipeDetail, NotFound) isolate specific views.

Navbar / Footer: Manages global navigation and active route highlighting.

UI Components: Button, Card, SearchBar, Modal, Loading, and EmptyState act as highly reusable, presentation-only elements utilizing the children prop for a consistent design system.

Recipe Elements: RecipeList, RecipeCard, and RecipeFilter map arrays of data and handle complex filtering logic.

Planner Elements: MealPlannerPage constructs the 7-day layout and individual breakfast, lunch, and dinner dropdown slots directly within the page.

Media Elements: VideoPlayer and AudioPlayer provide HTML5 multimedia wrapping for tutorials and tips.

4. State Management Strategy
Global state for saved recipes is managed using the Context API (FavoritesContext). This eliminates prop drilling and allows seamless sibling communication (e.g., clicking the save button in RecipeCard instantly updates the favorites count inside the Navbar).

The MealPlannerPage manages its own complex 3-slot daily schedule locally. It utilizes the useEffect hook to instantly synchronize any mutations with localStorage for browser persistence.

Local UI state (search queries, dropdown filters, loading states, and error handling) remains tightly scoped within parent components like RecipesPage to prevent unnecessary app-wide re-renders. Data fetching is simulated locally using setTimeout within a useEffect hook to demonstrate asynchronous state transitions.
